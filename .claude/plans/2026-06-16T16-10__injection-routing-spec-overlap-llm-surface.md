# План: маршрутизация поздних инъекций (#1 spec+file overlap → #3 surfaces → #2 LLM), fastest-first + short-circuit

## Контекст / проблема

Поздняя HITL-инъекция `красивый_вид` («MAKE THE NOTES NICE TO READ», нарочно без
UI-маркеров) **не влилась** в существующий узел `web_ui`, а создала параллельную
пустую ноду. Корень: инъекция прикрепляется на этапе **размещения корня**, а
текущий детектор overlap ищет существующий **файл** `src/web_ui.py` — которого
на тот момент ещё нет (строится позже, в той же фазе) → цели нет → новая нода.

Задача (слова юзера): реализовать **#1 + #2 + #3**, в порядке «сначала самые
быстрые», со **short-circuit** (нашёлся матч — остальные методы не гонять).
**#1 = overlap по СПЕКАМ нод + по файлам.** Переиспользовать и дополнить
существующий многометодный матчер (не плодить второй).

## Что переиспользуем (существующий матчер в `spec_flow_runner.py`)

| Элемент | Строки | Роль |
|---|---|---|
| `_AMEND_DETECTORS` + `_amend_detector(name)` | 684-688 | реестр детекторов (extend by register) |
| `_amd_explicit_file` | 691-694 | сигнал: инъекция называет файл модуля (O(1)) |
| `_amd_shared_route` | 697-700 | сигнал: общий HTTP-маршрут (O(1)) |
| `_amd_symbol_overlap` | 703-708 | токен инъекции = символ, который модуль ОПРЕДЕЛЯЕТ |
| `_amd_token_overlap` | 713-726 | доля общих токенов (floor 0.5) — самый рыхлый |
| `_amend_routes/_amend_tokens/_amend_symbols` | 654-684 | экстракторы сигналов из текста/кода |
| `_amend_find_owner(statement, modules, methods)` | 729-753 | селектор: max по детекторам, порог `_AMEND_MIN_SCORE` |
| `_amend_target(node)` | 1378-1405 | строит `modules` ИЗ ФАЙЛОВ, зовёт селектор |

Сейчас `_amend_find_owner` берёт **max по всем** детекторам по **каждому модулю**
из файлов. Нужно: (а) кандидаты из реестра нод+спек И файлов; (б) порядок
детекторов fastest-first со short-circuit; (в) + детектор поверхностей (#3);
(г) + LLM-роутер (#2) как медленный фолбэк.

## Жёсткие правила

- **Без хардкода / без keyword-list**: ни «/ui», ни «web», ни списка UI-слов.
  Все сигналы — универсальные (токены/символы/маршруты/поверхности из спек),
  семантику для неоднозначных случаев решает LLM-роутер.
- **Не плодить второй матчер** — расширяем `_AMEND_DETECTORS` и
  `_amend_find_owner`.
- **Free-only для LLM-роутера** — через `llm_backend.ask(..., role=..., step="")`
  (role/step теперь обязательны!). Дёшево: 1 вызов, только при провале быстрых.
- Дефолт поведения не ломать: p4/p5 не должны regress (short-circuit на быстрых
  детекторах = тот же результат, плюс новые кандидаты из спек только добавляют
  recall, не меняя существующие матчи по файлам).
- Тесты на каждый слой (позитив/негатив), полный `pytest tests/ -q` зелёный.

## Шаги

### Шаг 1 — Кандидаты из реестра нод + спек И файлов (#1)
`_amend_target(node)` (1378): кроме модулей-из-файлов, добавить **размещённые
узлы** как кандидатов. Для каждого узла-кандидата:
`(rel=node_id, stem=module_stem(node), body = spec_markdown + "\n" + file_body_if_any)`.
Так `_amend_symbols`/`_amend_tokens`/`_amend_routes` извлекут сигналы из **спеки**,
даже если файла ещё нет. Источник узлов — реестр движка (тот, где лежат
размещённые дети корня с их `spec_markdown`). Найти точку, где `_amend_target`
имеет доступ к дереву/реестру (self.nodes / tree), и собрать кандидатов оттуда.
Дедуп: если у узла есть и файл, и спека — один кандидат с объединённым body.

### Шаг 2 — Fastest-first + short-circuit в `_amend_find_owner`
Переписать селектор: вместо «max по всем детекторам разом» — идти по детекторам
в порядке стоимости и **возвращать первого владельца ≥ порога**, не запуская
более дорогие:
1. `explicit_file` (O(1) set)
2. `shared_route` (O(1) set)
3. `symbol_overlap` (string-set)
4. `token_overlap` (string-set, floor 0.5)
5. `surface_overlap` (#3 — структурный разбор спек)
6. `llm_router` (#2 — сеть, самый дорогой)

Для каждого детектора: прогнать по ВСЕМ кандидатам, взять лучшего ≥ порога;
если есть — вернуть, стоп. Порог на детектор (route/file=1.0; symbol≥0.6;
token≥0.5; surface≥своего; llm=бинарный). Параметр `methods` сохраняет
переопределение порядка/набора (env `SPEC_FLOW_AMEND_METHODS`).

### Шаг 3 — Детектор поверхностей `surface_overlap` (#3)
Зарегистрировать `@_amend_detector("surface_overlap")`. «Поверхность» узла =
структурно извлечённые из спеки сущности: маршруты (`_amend_routes`), имена
модулей/символов (`_amend_symbols`), + существительные-сущности (напр. «notes»,
«list», «form»). Матч = пересечение поверхностей инъекции и кандидата выше
порога. Универсально (из спек, не словарь). Ставить ПЕРЕД llm_router (дешевле).

### Шаг 4 — LLM-роутер `llm_router` (#2, медленный фолбэк)
Зарегистрировать `@_amend_detector("llm_router")`. Один вызов сильной модели:
вход = текст инъекции + список кандидатов `(id, краткая спека)`; ответ — id узла
или `new`. Реализация: детектор-функция сама не звонит (детекторы — чистые
скоринги); вместо этого в `_amend_find_owner`, если все детерминированные методы
дали 0, сделать ОДИН LLM-вызов через `llm_backend.ask(prompt, model=<verify/strong>,
role="reviewer", step="")`, распарсить id, вернуть. Бинарный матч (id→1.0 / new→0).
Безопасно: при ошибке/недоступности LLM → вернуть None (как сейчас) — поведение
не хуже текущего. Дать флаг `SPEC_FLOW_AMEND_LLM` (по умолч. вкл для p6, чтобы не
бить сеть в юнит-тестах — тесты передают `methods=` без llm_router или мокают ask).

### Шаг 5 — Тесты
- `surface_overlap`: спека web_ui («HTML page lists notes, add form») + инъекция
  «notes clean, tidy list, add one» → матч; несвязный узел → 0.
- short-circuit: если `explicit_file` дал матч, медленные (`token`/`llm`) не
  вызываются (счётчик вызовов).
- кандидаты-из-спек: узел web_ui БЕЗ файла (только spec_markdown) → инъекция
  всё равно маршрутизируется в него.
- `llm_router`: мок `ask` → возвращает id; при «new» → None; при исключении → None.
- регрессия: существующие amend-тесты (по файлам) зелёные.

### Шаг 6 — Прогон + коммит + живой p6
- `python3 -m pytest tests/ -q` зелёный.
- Коммит + push (ветка feat/roadmap-phase-1).
- Перезапустить живой p6 (v0NN) → по трассе убедиться: `красивый_вид` даёт
  `requirement → AMENDED into web_ui` (а не отдельную ноду), web_ui.py
  редактируется в месте. Дашборд :8092 — проверить дерево (нет параллельной ноды).

## Риск
- LLM-роутер может неверно влить → бинарный, только как ФОЛБЭК после
  детерминированных; при сомнении модель должна вернуть `new` (промпт это
  требует), и порог корректности на стороне последующего gate.
- Кандидаты-из-спек могут дать ложный матч рыхлым token_overlap → держать floor
  0.5 и доверять порядку (symbol/surface точнее token).
