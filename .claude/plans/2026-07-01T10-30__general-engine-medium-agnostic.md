## Остаётся (медиум-независимая перестройка, слайсами)

### Слайс 2 — типизированные рёбра графа зависимостей ✅ (`92bea1f`)
СДЕЛАНО: карточка узла получила `exposes:[символ]` + `needs:[{from,symbols}]`
(схема декомпозера просит); `_interface_edge_violations(tree)` — чистый гейт
плана (символ needs обязан быть в exposes производителя, иначе битое ребро до
сборки), диагностикой в plan-check, ленив к пустым (back-compat); declared
контракт кормится кодеру через `_interfaces_block` (вместе с реальными
интерфейсами #113с1). 10 офлайн-тестов вкл не-веб. Медиум-независимо.

### Слайс 3/4 — ЯДРА ГОТОВЫ (`cfb8f6b`), интеграция остаётся
СДЕЛАНО (чистые функции, 6 тестов): `_project_kind(texts)` (web|cli|lib|''),
`_synthesize_lib_entry(owner_by_symbol)` (реэкспорт API — не-веб аналог WSGI-роутера),
`_capability_probe_src(entry, symbol)` (приёмка по поведению — не-веб аналог boot-gate).
ОСТАЁТСЯ ИНТЕГРАЦИЯ: вшить в `_product_contract` (возвращать не-веб контракт по kind) +
`_product_check`/boot-gate (звать capability-probe для lib/cli). Без этого не-веб продукт
всё ещё судится только собранным набором. Это большой заход в ядро — следующим шагом.

### Слайс 3 (описание) — точка входа по ФОРМЕ проекта (не всегда WSGI)
`_synthesize_entry_code` сейчас всегда строит WSGI-роутер. Обобщить: форма входа
выводится из спеки — `main()`-диспетчер (CLI), реэкспорт в `__init__` (библиотека),
раннер (джоб/конвейер), WSGI (веб). Либо: точка входа = обычный узел с контрактом
«выставить верхнюю описанную способность». Контракт (`_product_contract`) даёт
`entry`+`exposes`; добавить `kind` (cli|lib|web|job). Не-веб проект получает
верную точку входа.

### Слайс 4 — приёмка по ПОВЕДЕНИЮ (не только curl HTTP)
boot-gate сейчас курлит `/health`. Обобщить: приёмка = исполнить ОПИСАННОЕ
поведение через собранный код. Для веба — HTTP-вызов (частный адаптер); для
CLI — запустить команду и проверить вывод; для библиотеки — импортировать и
вызвать API, проверить результат. Источник истины — контракт-приёмка (детерм.,
из спеки), а не сгенерированные юнит-тесты. Файлы: pytest_verifier boot-gate,
contract_checks.

### Слайс 5 — не-веб E2E кейс (доказать общность)
Добавить `tests/scenarios/pX_cli_or_lib.yaml` — проект БЕЗ HTTP (напр. CLI-утилита
или библиотека-парсер). Прогнать движок depth=product и получить честный READY
на не-веб продукте. Это ловит любой оставшийся HTTP-центризм.

## Правила
- Медиум-независимо: ничего HTTP-специфичного в ядре; веб — адаптер.
- Детерминированно кодом, промпт дублирует, гейт проверяет (не промпт-онли).
- Не ослаблять honest-гейты. Реальные баги чинит система (доктор), движок — мой.
- Офлайн зелёный → коммит → пуш. Тесты — free OpenRouter через Bifrost; claude
  подписочный. Прогоны отвязанно.

## Валидация всего
Свежий p6 (веб) при спокойном free-пуле до зелёного `meta.status=READY` +
не-веб кейс (слайс 5) до READY. Оба зелёных = движок реально общий, не веб-частный.
