# Базовые причины ошибок генерации (общий случай)

Контекст: разбор провала `delete_note` (прогон v041, дубль-поверхность) показал,
что точечные причины — частные случаи небольшого набора общих, инвариантных
для любой задачи.

Два принципа (ревизия):
- **Лечение всегда ведёт к рабочему результату.** Останов/долг — крайний
  предохранитель от бесконечного цикла, а не ответ на причину. В столбце лечения
  нет «бросить» — есть «откатить и перевыполнить», «вернуть конкретный узел на
  доработку», «достроить недостающее».
- **Профилактика важнее лечения.** Многие причины известны заранее и устраняются
  по дизайну (до запуска), чтобы ошибка не возникла вовсе. Лечение — для того, что
  профилактика не покрыла.
- **Лечение — это поиск решения, а не механический повтор.** Сначала найти
  корневую причину, затем привлекать ресурсы по нарастанию: сильнее ИИ → поиск в
  интернете и документации → человек-заказчик. «Откатить и перевыполнить» — лишь
  финальный шаг уже с найденным решением, а не само лечение.

Столбцы:
- **Причина ошибки** — что именно ломается.
- **Профилактика (заранее)** — как устроить работу, чтобы причина не возникла.
- **Лечение при детекте** — действие к рабочему результату (глагол; функция в коде).

| Причина ошибки | Профилактика (заранее) | Лечение при детекте (к рабочему результату) |
| --- | --- | --- |
| Слабый исполнитель — не держит указания под нагрузкой | Назначать модель по сложности узла заранее; сильная на трудное | Поднять на следующую модель и перевыполнить узел |
| Слишком крупная задача — нельзя проверить одной мерой | На разбиении держать предел «одна проверяемая дельта на лист» | Разбить на под-узлы и выполнить каждый |
| Нечёткая постановка — не ясно, что входит, а что справка | Генерировать контракт узла (зона/контекст/критерии) до старта | Уточнить контракт и перевыполнить узел |
| Лишние данные на входе — повторяет их вместо работы | Подавать только свою зону, соседей — ссылкой | Обрезать вход до своей зоны и перевыполнить |
| Проверка без права вернуть — видит изъян, пропускает | Дать проверке право возвращать узел на доработку | Вернуть конкретный узел на доработку (не пропускать) |
| Исправление переписыванием — повторяет ту же ошибку | Чинить точечной правкой по умолчанию | Применить дифф к найденным местам |
| Пустой результат — нет новой полезной части | Требовать новую дельту как условие приёмки | Вернуть на доработку с требованием конкретной дельты |
| Несогласованные проверки — один изъян судят по-разному | Один вердикт на изъян по единому ключу | Свести вердикты к одному итогу и применить его |
| Расхождение задачи и проверки — судят не то | Выводить пункты проверки прямо из требования | Согласовать проверку с требованием и переоценить |
| Случайность ответа — один вход даёт разный итог | Низкая температура + N голосов по умолчанию | Переспросить N раз, взять совпавший большинством |
| Нет связи с целью — верно по форме, не решает цель | Привязать к узлу исходную цель и критерий покрытия | Проверить покрытие цели; при пробеле доработать узел |
| Скрытые зависимости — опирается на ещё не готовый итог | Построить граф зависимостей и упорядочить запуск заранее | Достроить недостающую зависимость, выполнить в верном порядке |
| Молчаливое усечение — часть тихо отброшена | Запретить тихую обрезку; всё считать и логировать | Восстановить отброшенное и доработать узел |
| Накопление мусора — ранняя ошибка тянется дальше | Контроль качества на каждом шаге; не пускать дефект дальше | Найти корневой источник дефекта; привлечь ресурсы по нарастанию (сильнее ИИ → поиск в интернете/доках → человек-заказчик); затем откатить к чистому состоянию и перевыполнить с найденным решением |
| Потеря памяти/контекста — забыты прежние решения | По дизайну всегда подавать прежние решения и ограничения в контекст каждого запуска | Дозагрузить недостающие решения/ограничения и перевыполнить узел |
