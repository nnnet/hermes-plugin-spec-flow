# Переосмысление spec-flow: спека-IR как единственный источник, движок-компилятор

Дата: 2026-07-04. Контекст: v149–v164 — 16 прогонов, ~30 правил аудита,
v163 работал целиком, v164 снова сломан. Диагноз подтверждён юзером:
цель — УНИВЕРСАЛЬНЫЙ софт (каждый раз новые задачи, без памяти прошлых
проектов), спеки — единственный источник правды, независимость от
мощности модели. Кэш/инкрементальность отвергнуты как костыль-память.

## Корневая ошибка текущей архитектуры

ЛЛМ размазана по всем стадиям, стадии общаются ПРОЗОЙ. Каждая пара
прозаических артефактов — место дрейфа. Все правила S10.9–S12.16 — один
класс: «два артефакта разошлись в значении, не существовавшем как
данные». Аудит ловил рассогласования постфактум вместо их устранения
по построению. Урок v164: часть «прачечной» жила в детерминированном
коде самого движка (роутер-шаблон) — ревизия движковых шаблонов обязательна.

## Целевая форма

Единый машинный IR (структурированная спека): узлы графа + ПОЛНЫЙ
замкнутый интерфейс каждого узла (маршруты: метод/путь/статус/media/
форма запроса/форма ответа; символы с сигнатурами; конфигурация/env;
сценарии Given/When/Then первым классом). Всё, чего нет в интерфейсе, —
запрещено (закрытый мир). Из IR детерминированно КОМПИЛИРУЮТСЯ:
читаемые спеки, привязки, каркасы модулей, тесты соответствия, точка
входа, директивы лечения.

ЛЛМ ровно в двух местах:
1. описание → IR (схемная валидация + существующие план-гейты);
2. тела функций в движковом каркасе (каркас неприкосновенен — дверь).

## Граф работ

Каждый узел — по храповику: красные правила аудита ДО кода, красный И
зелёный кейс на каждый гейт. Исполнение: на каждом шаге искать узлы без
незакрытых зависимостей и вести их ПАРАЛЛЕЛЬНО (несколько исполнителей —
каждый в своём worktree); последовательно — только когда узлы толкаются
в одних файлах.
