# Аудит-гейтед храповик: дешёвый самоаудит гейтит дорогой прогон

## Принцип (юзер)
1. Аудит A+Б+В+…+Z (офлайн, секунды).
2. По итогам — правка.
3. Цикл 1↔2 до прохождения аудита (зелёный).
4. ТОЛЬКО после зелёного аудита — живой прогон (выявление ошибок).
5. Каждый НОВЫЙ провал прогона кодифицируется как НОВОЕ правило аудита (+Z),
   потом снова цикл 1↔2 → выход на 3. Дорогое открытие делается ОДИН раз, дальше
   ловится дёшево навсегда (храповик, не откатывается).

```
loop:
  audit (tests/audit)                      # секунды, офлайн
  ├ red → fix → goto audit                 # цикл 1↔2
  └ green → run-detached (живой прогон)     # шаг 3, гейт: только на зелёном аудите
       ├ green → DONE
       └ red → distill провал в НОВОЕ правило аудита (+Z) → fix → goto audit
```

## Что строим

### Уровень Б — инварианты честности (`tests/audit/`, чистые, без ЛЛМ)
Assert на движке + артефактах:
- READY ⟺ (все листья green) ∧ (все адреса служат) ∧ (suite green) ∧
  (integrate green) — логическое И как код (регресс #131).
- Каждый экспонирующий лист несёт полную карточку (file/handler/acceptance/
  examples); гейт enforced на card-capable плане, не lenient-навсегда.
- Нет заглушек в сгенерированном коде: `pass`/`NotImplementedError`/`TODO`/
  голый `return None` в теле хендлера.
- Роутер покрывает классы ошибок: 400 (пустое/битое тело), 404, 405, 500-safe.
- Каждый `(метод, путь)` резолвится в хендлер (нет unrouted).
- Каждый узел достигает терминала (нет тихого лимбо).
- Каждый гейт жив: reachable + реально краснит на своём негативном кейсе
  (нет мёртвого гейта).

### Уровень А — матрица классов требований → путь в движке
Таблица «класс требования → ветка движка». Красит класс БЕЗ пути.
Классы: new-route, **amend-in-place** (правка поведения существующего маршрута —
дыра v145 `красивый_вид`), delete-behaviour, duplicate (reject), non-web
capability, cross-cutting. Тест `test_every_requirement_class_has_a_path`.

### Уровень В — dry-plan (decompose+spec без сборки)
Флаг `--dry-plan` в раннере: прогнать decompose+spec на p-кейсах + синтетической
матрице требований, БЕЗ build (одна дешёвая модель, секунды). Отчёт: непокрытый
класс / лист без карточки / маршрут без хендлера. Это исполняемый чек-лист.

### Гейт прогона
`run-detached.sh` (или `run-guarded`) НЕ стартует, пока `pytest tests/audit`
красный. `make audit` + `bin` wrapper. Шаг 3 — только на зелёном аудите.

### Храповик (+Z)
Конвенция + шаблон: каждый провал живого прогона → новый файл-правило
`tests/audit/test_<class>.py`, кодифицирующий класс дефекта. Документируется в
`tests/audit/README.md`. Дорогое открытие → дешёвое правило навсегда.

## Первые +Z из v145 (сразу в аудит, красные до фикса)
- amend-in-place класс без пути (`красивый_вид`).
- card-completeness lenient пропускает лист без acceptance (`ping_text`).

## Порядок
1. Каркас `tests/audit/` + Уровень Б (инварианты) — часть уже есть как отдельные
   тесты, свести под один прогон.
2. Уровень А (матрица классов) + первые красные +Z из v145.
3. Гейт в run-detached + make/bin.
4. Уровень В (dry-plan).
5. #135 фиксы (amend-in-place путь + card-enforce) до зелёного аудита.
6. Только потом живой прогон p6/p7.

## Правила
Аудит честный: краснеет на реальной дыре, не подгоняется под зелёное. Не
облегчать. Прогон только через run-detached (setsid). claude=подписка Meridian.
