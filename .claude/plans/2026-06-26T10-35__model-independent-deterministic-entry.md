## 0. Цель и инвариант

**Цель:** собранный продукт служит весь контракт **независимо от того, какая
LLM** (сильная/слабая/деградировавшая) писала листья. Вариативность модели не
должна ронять сборку.

**Инвариант:** HTTP-glue (точка входа, роутинг, разбор тела, обработка ошибок,
сериализация) — **детерминированный код движка**. Модель отвечает ТОЛЬКО за тела
бизнес-логики листьев за фиксированным (мягко) ABI. boot-gate остаётся честным
оракулом (round-trip персистентности роутер подделать не может).

**Три мода провала (наблюдены v086/v087/v088):**
- **M1** — `json.loads` без try/except → 500 вместо 4xx (v086).
- **M2** — поздний маршрут (`/ui`,`/about`) не вшит в entry → 404 (v087).
- **M3** — пере-расщепление, ни один лист не даёт WSGI-callable → нет точки
  входа (v088).

**Уже закрыто (не переделывать):** git-сиротение листьев + split продукта
(7 фиксов; merge>0/merge_failed=0, инвариант молчит на 3/3); контракт из
человеческого текста (`_product_contract`); AST-карта API (`_existing_src_api`);
детектор ривала (`_rival_wsgi_entries`); boot-gate с malformed→4xx (a8346c5).

## ФАЗА 1 — детерминированный синтез entry (ядро; начинаем отсюда)

Делаем TDD: тесты → код → офлайн-набор → отвязанный p6-прогон.

### 1a. `_resolve_route_handlers(self, contract) -> (mapping, unresolved)`
Чистый AST, без исполнения. Для каждого объявленного маршрута `(method, path)`
ищет в `src/*.py` функцию-кандидат, скорит по:
- **сигнатуре**: `(payload, query)` (высокоур.) ИЛИ `(environ, start_response)`
  (сырой WSGI) ИЛИ `(payload)`;
- **совпадению токенов** имени с method+resource:
  `POST /notes` ↔ `post_note`/`notes_post`/`create_note`/`add_note`;
  `GET /notes` ↔ `get_notes`/`notes_get`/`list_notes`;
  `GET /ui` ↔ `ui_get`/`get_ui`/`ui`/`render_ui`/`index`;
  `GET /about` ↔ `about`/`about_page`/`get_about`;
  `DELETE /notes/{id}` ↔ `delete_note`/`remove_note`.
Берёт лучший скор на маршрут. Возвращает
`{(method,path): (module, func, abi)}` + список нерезолвленных маршрутов.

### 1b. `_synthesize_entry_code(self, contract, mapping) -> Optional[str]`
Эмитит исходник роутера (stdlib-only, без сторонних зависимостей):
- импорт резолвленных модулей листьев;
- ROUTES-таблица из объявленных маршрутов (+ простой шаблон `{id}` → param);
- `wsgi_app(environ, start_response)`:
  - разбор `method`, `path`, `query` (`urllib.parse`), `body` по CONTENT_LENGTH;
  - **тело с guard**: `try: payload = json.loads(body) if body else {} except
    Exception: → 400 {"error":"invalid json"}` (**M1 решён для всех продуктов**);
  - match пути: точный + шаблон `{id}`; нет пути → **404**; путь есть, метод не
    тот → **405**;
  - вызов хендлера по ABI: высокоур. `(status, body)` адаптируется в WSGI-ответ;
    сырой WSGI делегируется напрямую (`return handler(environ, start_response)`);
  - сериализация: dict/list → json + `application/json`; str c `<` → `text/html`;
    иначе `text/plain`; статус-строка, `start_response`, `return [bytes]`;
  - экспорт объявленного callable (`wsgi_app`; alias `application = wsgi_app`).
- health/ok_route без листа → инлайн 200 `{"status":"ok"}` (безопасный синтез).
- Возвращает `None`, если **критический** маршрут (json_roundtrip) не резолвится
  → честный фолбэк на LLM (не подделываем бизнес-логику).

### 1c. Детерминированно-первый в точках сборки
Точки: `_remedy_reconcile_check` (реактивный, ~2411) и проактивный build узла
`product_entry`. Перед `_invoke_implementer`:
1. `code = self._synthesize_entry_code(contract, mapping)`;
2. если `code`: записать в entry, закоммитить (через тот же commit-авторитет),
   `boot_ok,_ = self._assembled_product_boots()`; зелёно → **готово без LLM**
   (детерминированный путь, метрика `entry_synthesized=True`);
3. иначе фолбэк на текущую LLM-директиву (ей же отдать частичный роутер как
   опору/контекст).
Эмиттить trace-событие `entry synthesized (deterministic)` / `entry via LLM
(fallback)` для дашборда и замеров.

### 1d. Закрыть v088-щель (entry есть, но без callable)
`_assembly_node`: условие запуска сборки расширить — запускать и когда
`entry.is_file()` ИСТИНА, но `_entry_exposes_callable(entry, callables)` (новый
AST-хелпер) == False, не только при наличии ривала. Сейчас skip-условие
`entry.is_file() and not _rivals` ложно пропускает этот случай.

### 1e. Зафиксировать ABI листа — МЯГКО (выбор юзера)
- директива в `_assembly_node` + гайданс декомпозера: HTTP-эндпоинт листа =
  `def <name>(payload, query) -> (status:int, body:dict|str)`;
- роутер из 1b **всё равно адаптирует и сырой WSGI** (defensive) — мягкость:
  не ломаем листья/продукты, которые отступили от ABI;
- НЕ ужесточать ревью под этот ABI (это сломало бы p4/p5). Только подсказка.

## ФАЗА 2 — AST пост-процессор (страховочная сетка для M1)
**`_harden_entry(entry_path)`** — кодемод (`ast`/при наличии `libcst`) поверх
ЛЮБОГО entry (LLM-написанного ИЛИ синтезированного):
- обернуть незащищённый разбор тела (`json.loads`/`json.load` на `wsgi.input`)
  в try/except → 400;
- гарантировать экспорт контрактного callable (добавить `application = wsgi_app`
  при отсутствии).
Прогон сразу после LLM-сборки. Только ПОВЕРХ каркаса (не маскирует поломку
плана — её ловит Фаза 3). Гард-тест: голый `json.loads` оборачивается, alias
добавляется, идемпотентность (повторный прогон ничего не меняет).

## ФАЗА 3 — статический гейт плана декомпозиции (до кода, ловит M3 в корне)
По мотивам reharness (definite-assignment) + Spec Kit (analyze):
- **structured output**: декомпозер возвращает план строгой JSON-схемой
  (узлы, контракты, объявленные маршруты, который узел даёт entry).
- **инвариант плана** (детерминированная проверка ДО кодогенерации):
  - reachability: каждый узел достижим, нет тупиков;
  - **ровно один лист производит entry-callable**;
  - **каждый объявленный маршрут имеет лист-производитель** (покрытие);
  - нет дублей-производителей одного маршрута (route-redeclare ловится тут, не
    на ревью).
- нарушено → детерминированно вставить недостающий assembly/handler-узел ДО
  генерации, либо схлопнуть пере-расщепление (объединить notes_get+notes_post в
  один лист, если контракт того требует).

- Параллелизм НИКОГДА не выключать; worktree-изоляция сохраняется.
- boot-gate — честный оракул; round-trip персистентности роутер не подделает →
  «красный честный > зелёный лживый».
- Пост-процессор (Фаза 2) только ПОВЕРХ каркаса; поломку плана ловит Фаза 3.

  — прежний LLM-путь; регресс-замер p4/p5 после Фазы 1 (нужен
  `workers.claude_gateway` в их yaml, иначе preflight откажет — это корректно).
