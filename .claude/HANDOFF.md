## Сделано этой сессией — #128 (закрывает подкласс A, `8b70933`, офлайн 465)
`repair_local_imports` (pytest_verifier): по таблице символов `src` детерминированно
переписывает `from X import Y` на реального единственного владельца Y. Без LLM, без
провайдера, **медиум-независимо** (CLI/библиотека/конвейер — как веб; ничего
HTTP-специфичного). Врезан перед `run_all`. Символ без владельца / у >1 — не трогает
(честный RED). 7 тестов вкл НЕ-веб конвейер. На реальном v137 корректно вернул `[]`
(там подкласс B — угаданы имена, чинить нечего без угадывания).

## ИСТИННЫЙ КОРЕНЬ — #113 (подкласс B, следующий и главный)
Потребитель угадывает, что ПРОИЗВОДИТ сосед. Лечится не починкой (имя не вывести без
угадывания), а **публикацией интерфейса**: когда лист кодируется, дать кодеру РЕАЛЬНЫЙ
интерфейс уже собранных зависимостей (имя модуля + публичные символы + сигнатуры,
детерминированно из AST) — тогда `web_ui` импортит `create_note`, а не `save_note`.
Топо-порядок (#42) гарантирует, что зависимости собраны раньше → их интерфейс
извлекаем. Форма #113: КОД публикует интерфейсы как данные (`_src_public_symbols`
уже есть, добавить сигнатуры) + ПРОМПТ кодера/доктора получает срез + ГЕЙТ ловит
остаток (уже есть). Это меняет контекст `_invoke_implementer` — аккуратно, на свежем
контексте.
