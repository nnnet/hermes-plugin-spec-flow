# docs/ — что здесь лежит

Чтобы не было «старых несуществующих отчётов», здесь ровно два типа файлов:
**источники** (пишутся руками) и **генерируемые отчёты** (создаёт
`tests/report.py`; перегенерируются одной командой, в git как снимок).

| Файл | Тип | Что это |
|---|---|---|
| `conversation.md` | источник | стенограмма исходного чата (откуда взялся плагин) |
| `analysis.md` | источник | разбор: что собрали и как легло на репозиторий |
| `test-report.md` | генерируется | деревья декомпозиции, дрейф контрактов, таймлайн ресёрча |
| `business-scenarios-report.md` | генерируется | ловля намеренно размытых бизнес-постановок (policy_gate) |
| `full-run-report.md` | генерируется | **реальный прогон**: footprint + методологический аудит (зелёный) |
| `flawed-run-report.md` | генерируется | **битый пример**: тот же аудит ловит нарушения |
| `full-run-trace.jsonl` | артефакт (в `.gitignore`) | сырой событийный лог реального прогона — источник для отчётов |
| `run-workspace/` | генерируется | **материальные артефакты прогона** для оценки: `specs/` (планы по узлам), `contracts/` (замороженный контракт), `src/` + `tests/` (заготовки кода/тестов), `COMMITS.md` (журнал коммитов), `MANIFEST.json` (типы/размеры/sha256) |

Перегенерировать всё:

```bash
python3 tests/report.py
```

Отчёт по любому своему трейсу строит сам плагин:

```bash
python3 tests/run_report.py <trace.jsonl>      # в Hermes: run_report(trace_path=...)
```
