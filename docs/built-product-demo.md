# Демо собранного продукта: проверить руками, что система работает

Плагин на глубине `execute` выдаёт не отчёт, а **работающее приложение**
в workspace прогона. Этот документ — как поднять его и убедиться в
работоспособности осмысленной последовательностью запросов.

Эталон: прогон кейса `p5_mvp_marketplace` (B2B-маркетплейс
восстановленного оборудования), прошедший приёмку — корневая интеграция
PASS на настоящем pytest, сквозной смоук зелёный.

## 1. Поднять продукт

```bash
python3 tests/serve_product.py \
  --workspace tests/runs-out/<прогон>/workspace --port 8508
```

Раннер монтирует приложение **без правок** (добавляет только титульную
страницу `/` с контрактом) и заводит свежую sqlite-базу во временном
каталоге. Браузером: `http://<хост>:8508/`.

С удалённой машины — туннель через тот же SSH, которым заходите на хост:

```bat
ssh -L 8508:127.0.0.1:8508 <user>@<хост>
```

дальше все запросы на `http://localhost:8508`.

## 2. Осмысленная последовательность проверки

История: новый продавец выходит на маркетплейс, выставляет товар,
покупатель находит его поиском и покупает, продавцу начисляется выплата.

Синтаксис ниже — Windows cmd.exe (кавычки JSON экранируются `\"`);
в bash используйте одинарные кавычки вокруг тела.

```bat
:: 1. Регистрация продавца — id и сразу проверенный KYC (заглушка)
curl -s -X POST http://localhost:8508/sellers -d "{\"name\":\"Ural Servers\",\"email\":\"sale@ural.io\"}"
::    -> {"id": N, ..., "kyc_status": "verified"}     запомните N

:: 2. Товар этого продавца (подставьте N)
curl -s -X POST http://localhost:8508/products -d "{\"seller_id\":N,\"title\":\"Xeon blade refurb\",\"price_cents\":129900}"
::    -> {"id": P, ...}                               запомните P

:: 3. Покупатель ИЩЕТ товар по слову из названия — находится
curl -s "http://localhost:8508/products?search=blade"

:: 4. Контроль честности поиска: чужое слово — пустой список
curl -s "http://localhost:8508/products?search=nonexistent"
::    -> {"items": []}

:: 5. ДО покупки выплат у продавца нет (подставьте N)
curl -s "http://localhost:8508/payouts?seller_id=N"
::    -> {"items": []}

:: 6. Покупка (подставьте P) — заказ сразу оплачен заглушкой платежей
curl -s -X POST http://localhost:8508/orders -d "{\"product_id\":P,\"buyer_email\":\"cto@buyer.io\"}"
::    -> {"id": ..., "status": "paid"}

:: 7. ПОСЛЕ покупки выплата ПОЯВИЛАСЬ, сумма равна цене товара
curl -s "http://localhost:8508/payouts?seller_id=N"
::    -> {"items": [{"order_id": ..., "amount_cents": 129900, "status": "paid"}]}

:: 8. Неизвестный маршрут — честный 404, а не падение
curl -s http://localhost:8508/admin
```

## 3. Что именно доказывает последовательность

- **Шаги 5 → 6 → 7 — причинность**: выплата возникает только из
  оплаченного заказа и ровно на сумму товара. Это главная бизнес-инвариант
  кейса, не «ручка отвечает».
- **Шаг 4** — поиск не возвращает мусор (отрицательный контроль).
- **Шаг 8** — приложение осмысленно отвечает и на то, чего нет.
- Последовательность повторяет приёмочный смоук плагина
  (`tests/smoke/test_mvp_smoke.py`) по живой сети, чужими руками — то
  есть результат воспроизводим вне тестовой обвязки.

## Частые ошибки подключения

- `http://0.0.0.0:8508` — так нельзя: `0.0.0.0` — адрес *прослушивания*
  на сервере, не назначения. Используйте адрес хоста или туннель.
- Одинарные кавычки вокруг JSON в cmd.exe не работают — тело уйдёт
  искажённым; экранируйте двойные (`-d "{\"k\":\"v\"}"`).
- Флаг `-s` прячет ошибки соединения — при «ничего не возвращает»
  уберите его и смотрите причину.
