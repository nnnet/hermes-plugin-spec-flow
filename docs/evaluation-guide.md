# Как оценивать тесты spec-flow (гайд для ревизионера)

## Главный принцип

Плагин — **оркестратор**, не генератор кода. Он решает: что разбить, что
заморозить, когда заблокировать, кого вернуть на доработку. Тесты проверяют
**решения и порядок действий**, а не качество сгенерированного кода.

Код в `workspace/src/` пишет внедряемый агент-исполнитель. Встроенный — это
осознанная детерминированная заглушка: она доказывает, что **механика передачи
работы агенту исправна** (вызван для каждого листа, после нужных проверок, со
спекой на входе, выход попал в воркспейс и прогнан pytest'ом). Качество кода —
свойство живого агента, который подключается параметром `agents=`.

## Вопрос ценности: «упадёт ли тест, если плагин сломать?»

Хороший тест на оркестрацию падает от поломки **решения**, а не от смены
формулировки. Проверка для каждого теста:

| Если сломать… | Какой тест упадёт |
|---|---|
| пороги `leaf_check` | граф декомпозиции разойдётся с эталоном (`test_decomposition_graph`) |
| сравнение контракта с кодом | дрейф не пойман / ложный дрейф (`test_contract_drift`) |
| условия `policy_gate` | размытая постановка пройдёт без блока (`test_policy_scenarios`) |
| курок ревизии / кулдаун | ревизия не выстрелит или зациклится (`test_research_timeline`) |
| любой цикл (clarify, критика, respec) | полный прогон не покажет цикл (`test_full_run`) |
| правило аудита R1–R8 | битый след перестанет ловиться (`test_run_report`) |

## Что смотреть в папке прогона (`tests/runs-out/<метка>__<кейс>/`)

1. `SUMMARY.md` — вердикты: блок размытой цели, покрытие, аудит.
2. `policy-report.md` — что именно гейт поймал в размытой постановке
   (это вход теста: неточность намеренная, ловить её должен плагин).
3. `report.md` — footprint: видно **где крутилось** (clarify, критика,
   дрейф→respec, ревизия) и **чем закончилось**; внизу — аудит метода.
4. `workspace/specs/` + `contracts/` + `MANIFEST.json` — материальные
   артефакты: каждая вершина дерева получила план, контракт заморожен.
5. `workspace/TEST-RESULTS.md` — честность глубины: на `verify` заготовки
   **красные** (никто не писал код — тесты и не должны проходить), на
   `execute` — зелёные (код написал агент).

## Лестница глубины — что доказывает каждый уровень

| Глубина | Что доказано |
|---|---|
| `spec` | решения: гейты, дерево, контракты, манифест |
| `scaffold` | материализация: файлы, журнал коммитов |
| `verify` | честная проверка: настоящий pytest, красное = красное |
| `execute` | передача работы агенту: его код попал в проект и прошёл тесты |

## Признаки плохого теста такого рода (анти-чеклист)

- проверяется текст лога, а не вердикт проверки;
- проверка замокана (дрейф «найден» без сравнения файлов);
- аудит никогда не видел битого следа — нечем доказать, что он не «всегда зелёный»;
- кейс без намеренной неточности — нечего ловить гейту;
- артефактов нет — после прогона нечего предъявить ревизионеру.

## Что эти тесты НЕ проверяют (и не должны)

- качество кода живого агента-исполнителя — это его свойство, не плагина;
- работу самого Hermes (доска, диспетчер) — прогоны автономные;
- осмысленность текстов спек — спеки здесь носитель трассировки, не контент.


## Суть коротко:

  **Заглушки в src/ — норма, потому что тестируется не код**. Плагин — оркестратор: его продукт — решения (блокировать/разбивать/замораживать/возвращать), а код пишет внедряемый агент, который в
  плагин не входит. Уровень execute доказывает только механику передачи работы агенту: вызван для каждого листа, после гейтов, со спекой, его выход прогнан pytest'ом. Подключишь живого агента —
  код станет настоящим, обвязка уже проверена.

  **Главный вопрос к любому такому тесту: «упадёт ли он, если сломать решение плагина?»** Здесь — да: сломаешь пороги — разойдётся граф с эталоном; сломаешь сравнение контрактов — не поймается дрейф
  (сравнение настоящее, по файлам); сломаешь гейт политики — размытая постановка пройдёт без блока; сломаешь правило аудита — перестанет ловиться битый след.

  **Что смотреть в папке прогона:** SUMMARY.md (вердикты), policy-report.md (что поймано в размытой постановке), report.md (где крутилось и чем кончилось + аудит), workspace/ (артефакты),
  TEST-RESULTS.md (честность: на verify красное, на execute зелёное).

  **Анти-чеклист** (признаки бесполезного теста): проверка текста лога вместо вердикта, замоканные проверки, аудит без битого примера, кейс без намеренной неточности, прогон без артефактов.
