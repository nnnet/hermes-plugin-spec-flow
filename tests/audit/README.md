# tests/audit — самоаудит движка (дешёвый гейт перед дорогим прогоном)

Цель: ловить **дыры проектирования** (отсутствующая ветка логики, заглушка,
недостающая часть, класс требования без пути) статически/дёшево — за секунды,
без часового живого прогона.

## Храповик (ratchet)

```
loop:
  pytest tests/audit           # секунды, офлайн, без ЛЛМ
  ├ red  → правка движка → goto loop
  └ green → живой прогон (run-detached)   # только на зелёном аудите
       ├ green → DONE
       └ red  → distill провал в НОВОЕ правило tests/audit → goto loop
```

Дорогое открытие (живой прогон) делается по классу дефекта ОДИН раз. Дальше тот
же класс ловится этим аудитом бесплатно навсегда — храповик не откатывается.

## Уровни

- **Уровень Б — инварианты честности** (`test_honesty_invariants.py`):
  READY = логическое И; синтезированный роутер без заглушек и с ветками
  400/404/405; каждый (метод,путь) резолвится; карточка листа полна; гейты живы.
- **Уровень А — матрица классов требований** (`test_requirement_class_paths.py`):
  каждый класс требования (new-route, amend-in-place, delete-behaviour,
  duplicate, capability, cross-cutting) имеет НЕ-отклоняющий путь в движке.
  Красит класс без пути (дыра v145: amend-in-place прозы «сделай красиво»).
- **Уровень В — dry-plan** (позже): decompose+spec без сборки → отчёт непокрытых
  классов / листов без карточки / маршрутов без хендлера.

## Как добавить правило (+Z) после провала прогона

1. Возьми терминальную причину из `runs-out/.../trace.jsonl` (напр. «empty_delta
   → reject» на легитимной правке).
2. Сведи к КЛАССУ (не к конкретной фразе): «правка существующей поверхности не
   должна становиться отклонённым форком».
3. Добавь дешёвый детерминированный тест сюда, красный до фикса.
4. Почини движок (не тест). Аудит зелёный → прогон.

Правило: аудит честный — краснеет на реальной дыре, НЕ подгоняется под зелёное.
Никаких костылей/заглушек ради прохождения.
